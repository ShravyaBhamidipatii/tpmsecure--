tpmsecure // predictive disk-encryption safety

Your disk encryption shouldn't lock you out for doing the right thing.

TPMSecure predicts when a routine security update will break TPM-sealed disk unlock — before it happens — and verifies the device's own hardware identity before ever re-sealing the key.

The problem with TPM-sealed encryption today

TPMs bind a disk's decryption key to measurements of the boot process. That's the whole point — it proves nothing was tampered with. But it has a sharp edge.

what should happen

You install a routine firmware or bootloader update. The system reboots. Everything unlocks normally.

what actually happens

The update changes a measured value. The TPM no longer recognizes the boot state. The disk refuses to unlock — with no warning beforehand.

Four gates, in order

Click each stage to see what it actually checks.

01

Pre-flight prediction +

Before any update is applied, TPMSecure predicts what the resulting boot measurements would be and compares them against what's currently sealed — catching a coming lockout while there's still time to warn the user.
02

PCR verification +

After the update completes, the real boot measurements are checked against what was predicted. A mismatch here means something unexpected happened — re-enrollment stops immediately.
03

Device authentication +

A matching PCR state alone isn't proof of identity — it could in principle be satisfied by different hardware presenting the same measurements. This gate requires a valid TPM-backed device certificate too.
04

Automatic re-enrollment +

Only once both checks pass does the system reseal the disk key against the new, verified boot state — automatically, with no manual recovery key entry.

Why this matters

A locked-out disk isn't an inconvenience — it's downtime, lost access, and in some cases data that's effectively gone until a recovery key surfaces.

servers

A remote server that fails to unlock after a routine patch means a physical visit or a painful out-of-band recovery process — TPMSecure catches the mismatch before the reboot that would cause it.

developers

Workstations with full-disk encryption are common in security-conscious teams. An unplanned lockout costs a day of work recovering keys instead of shipping.

security teams

The device certificate gate closes a real gap: a PCR match alone can't distinguish the original trusted hardware from a different device presenting the same measurements.

TPMSecure — built on TPM 2.0, LUKS2, systemd-cryptenroll, and systemd-pcrlock.
